# Security and evidence handling

Use only with explicit authority and on acquired working copies within the documented scope. This is personal lab engineering, not a security product, certified forensic suite or universal incident-response procedure.

The public source edition omits vendor runtime/media, device-pinned installers and the operative release manifest. Do not bypass a missing dependency, manifest mismatch, execution policy, Application Control or security warning. Review and independently validate a staged environment before operational use. Do not execute evidence or treat a container as a malware sandbox.

Never open a public issue containing private evidence, original case reports, credentials, device identifiers or unredacted operational logs. For a suspected vulnerability, use GitHub's private vulnerability-reporting option if enabled, or raise a minimal non-sensitive request for a private reporting channel. No private reporting service or response SLA is promised.

Generated-log cleanup changes the active case and must follow preview, protected full archive, typed confirmation and manifest-lineage rules. Use archive only when the original case must remain immutable. ZIP archives are not automatically encrypted; file removal is not secure erasure. Interrupted cleanup remains review required.
